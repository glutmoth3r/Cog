# Cog JIT design and implementation record

## Goal

Cog's Cranelift JIT is an opt-in optimization for hot synchronous bytecode.
Generated code can execute operations directly, call the runtime synchronously,
or restore the interpreter frame at a precise bytecode position. The interpreter
defines observable behavior. Metered execution remains in the VM.

JIT V1 is successful when it can safely select work that is likely to repay compilation, preserve VM behavior at OSR and fallback boundaries, and demonstrate repeatable end-to-end results. The adaptive model is advisory; it must never affect program correctness.

## V1 baseline

- The CLI and Rust SDK can opt into Cranelift JIT. The machine-code plan is retained for the lifetime of a VM execution plan.
- Runtime bytecode generation folds closed scalar and bounded BigInt expressions, including eligible small constant calls. Small statically typed scalar helpers can be inlined when their bodies contain only pure expressions and local `const` bindings; removing the call frame exposes more work to constant propagation and JIT lowering. BigInt folding is limited by the comptime evaluator's node and allocation budgets.
- Compiler-generated bytecode runs through a bounded CFG pass before final verification. It propagates scalar constants through local slots and the operand stack, folds only successful scalar operations, removes known conditional edges and unreachable blocks, and replaces redundant local stores with `pop`. Regions beyond the analysis budget remain unchanged; the optimized artifact is verified before use.
- After rewriting each callable, bounded CFG liveness colors non-overlapping local lifetimes into shared frame slots. This reduces interpreter frame storage and the number of roots copied during OSR; over-budget regions keep their original slots.
- APE uses three backedge windows, a limited bootstrap probe count, shared calibration, a compile token bucket, and caps of 512 functions and 64 MiB of executable memory. Active candidates are compared by priority at profile-window boundaries, and stale candidates do not block selection.
- OSR currently requires an empty operand stack. The frame carries tagged locals and stack slots; errors and unsupported operations return to the interpreter.
- Lowering covers checked `int` and `uint` arithmetic, `float` add/subtract/multiply/divide, same-type numeric comparisons, exact mixed `int`/`uint`/`float` comparisons, and compact signed/unsigned BigInts. Arbitrary-size BigInt add/subtract/multiply/divide/remainder and comparisons use checked synchronous runtime helpers; unsupported types and zero divisors resume in the VM. A JIT function may call a previously calibrated pure Cog function through a reusable VM frame. The initial native-call fast paths cover numeric `str::to_bigint`, checked `bytes::set`, and checked `bytes::get`; unsupported values and invalid arguments resume before the operation. Other lowered operations include `char` ordering, boolean equality, `nil` equality/inequality, boolean operations, primitive and registered enum/variant type tests, `!!` propagation state, and branches.
- Tagged frame slots can retain strings, BigInts, errors, arrays, and other opaque values as VM roots. Arrays have a dedicated slot kind so `ConstrainArrayFrom` resumes the VM only when array metadata may actually change. Known enum variants additionally carry a bytecode-local tag id in the slot tag; the rooted Cog value still owns the full nominal tag and payload. Unknown variants and errors fall back to the VM for full-name matching.
- `src/bin/bench_jit.rs` compares matched VM and JIT-enabled integer, unsigned integer, float, enum/variant, mixed integer/float, BigInt/float, BigInt arithmetic, inline BigInt helpers, signed/unsigned BigInt division/remainder, compact mixed-representation BigInt arithmetic and overflow fallback, compact signed/unsigned BigInt comparisons, and a fixed-point Mandelbrot render. The render benchmark covers the whole bytecode path: coordinate generation, large-BigInt escape checks, pure Cog calls, and indexed `bytes::set`, then checks a pixel checksum. Its profiles and Cargo temporary files live under `target/`; set `COG_JIT_BENCH_DEBUG=1` to print JIT selection and fallback diagnostics.

## V2 synchronous call bridge

- Direct calls first try the existing compiled-callee adapter for compatible
  pure functions in the same execution plan. On a guard miss, the bridge runs
  the call through the ordinary VM loop and stops at the caller's following
  instruction after the call frames unwind. Nested and recursive calls use
  ordinary VM frames. The invocation reuses its operand, local, and call-frame
  buffers across bridge calls. The outer JIT keeps its locals in SSA.
- A compiled callee is side-effect free: besides scalar and aggregate
  construction it may read captures, return through a propagating return,
  and make direct calls to callees that are side-effect free as well
  (recursion included). Compiled callees therefore nest: each nested call
  runs in a pooled child frame that shares the caller's roots and releases
  the callee's temporary roots on return. Nesting is limited to 32 native
  frames. A compiled callee never enters the VM bridge. Any fault, fallback,
  Error result, or depth overflow discards the whole chain of compiled
  callees, and the outermost call runs in the VM (from an OSR loop) or the
  caller resumes at the call instruction (when the VM entered it). The VM
  then reproduces errors and traces itself. Eligibility does not imply native
  coverage: an unlowered instruction, such as aggregate construction, ends
  the compiled attempt in the same way.
- `CallValue` targets that are closures or bound function values owned by
  the running program use the same adapter when their body is compiled and
  side-effect free; captures are passed through the child frame. Other
  targets, foreign owners, and closures that update mutable cells use the VM
  dispatch below. Calls that miss the adapter in an OSR loop are counted,
  including direct calls missed inside compiled callees, so hot
  side-effect-free callees and closure bodies compile once the loop leaves
  native code, and the next OSR entry uses them.
- Indirect calls use the same VM dispatch as interpreted calls. It checks the
  callable's current program owner, signature, and captures on each call.
  Named function values, scalar and reference captures, mutable cells, and
  changing targets work through this path. Higher-order standard-library
  loops use the same lowering when their bytecode is eligible.
- Synchronous builtins and registered imports use the linked native dispatch.
  Rust SDK and C ABI v3 effects, capabilities, argument checks, results, and
  call-scoped handles retain their existing contracts. The existing bytes and
  numeric BigInt conversion specializations remain available.
- A helper spills only the operands it consumes and reloads one result.
  Managed arguments and captures preserve their identity. The general bridge
  reserves result space before dispatch, so a capacity miss can resume before
  an operation with effects. Array updates can reuse the input root. Array
  indexing, indexed writes, length, and scalar `append`/`prepend` calls have
  tagged fast paths for common inputs; a push validates the element before
  mutating, and a rejected value goes through the VM bridge, which reports the
  error. Other supported index, length, and push cases use shared VM handlers.
- The VM bridge carries the propagation bit in both directions. A returned
  Error resumes the VM **after** the operation with the Error on the stack
  and its origin recorded. The VM then performs observation, propagation and
  cleanup. Terminal failures preserve the failing bytecode location. If frame
  validation fails after a committed operation, execution terminates to avoid
  replaying effects.
- Cog VM bridging is restricted to artifacts without scheduler instructions,
  a halt instruction inside a callable, or exclusivity observations. A nested
  VM call cannot suspend its native caller, and extra JIT roots would affect
  reference count observations. Bridged callees run in the VM until they
  return. Unsupported instructions still resume at the current bytecode PC.
- APE version 18 invalidates earlier timings, because nested compiled
  callees, compiled closure calls, and native pushes changed which code runs
  natively. Probe time includes synchronous bridge work. Failure, cooldown,
  and compilation-budget rules still apply. JIT debug output records compiled callees, Cog and native bridge calls,
  specialized native calls, aggregate operations, time inside bridge dispatch,
  fallback PCs and reasons, and generated code size. Host-specific benchmarks are
  recorded in the repository development evidence.

## Runtime contracts

### OSR frame and exits

The frame is private to one synchronous native call. `JITModule` owns all executable memory for as long as an entry pointer can be used. Generated code can call only the private synchronous helpers registered with that module. The frame carries an invocation-scoped helper context and root-vector pointer; neither is retained after the native call returns. Helpers report unsupported values without changing the operation's inputs, so the interpreter can retry the original bytecode instruction.

Each native return must be validated as a tuple of status, reason, bytecode PC, and stack depth before any returned slot is copied into the interpreter. The accepted cases are:

| Exit | Required state | VM action |
| --- | --- | --- |
| Completed | Normal reason; PC points at a reachable `Return`; analyzed stack depth matches | Restore frame, then let the VM execute `Return` and commit its normal result semantics |
| Resume | Normal reason; PC is a reachable instruction with the analyzed stack depth | Restore frame and resume at that exact instruction |
| Profile slice | Resume status; empty-stack OSR target; budget exhausted after at least one backedge | Restore frame and continue profiling in the VM |
| Fault | Normal reason; PC is an instruction where lowered execution may detect a runtime fault; pre-instruction frame | Restore frame and let the VM reproduce the canonical error |

Unknown statuses, impossible status/reason pairs, invalid PCs, bad slot tags, invalid roots, or inconsistent depths are rejected. Rejection disables the compiled candidate. The interpreter can resume from the original OSR state before effects have committed. After a committed runtime operation, an invalid exit is terminal.

Normal dynamic fallback and runtime faults are not compiler failures. They may trigger a bounded interpreter cooldown before another OSR attempt, but must not permanently poison eligibility for different runtime values. Deterministic Cranelift failures and corrupt native frames may disable the candidate for that execution plan.

### APE and profiles

- Separate the bootstrap exploration rule from adaptive profitability decisions. Never require measurements that can only exist after the first successful compilation.
- Treat compile tokens as a CPU-share budget, not a hard latency bound: Cranelift is currently called synchronously and cannot be preempted. An oversized estimate must not create a permanently impossible admission condition; account for over-budget compilation as debt and refill it over time.
- For an uncalibrated candidate using shared speedup data, charge its conservative static compile estimate. A missing per-function compile measurement must not be treated as a near-zero cost.
- Persist measurements that can inform a later run. Current-run heat, active-window qualification, and remaining activity horizon must reset at process start.
- Validate loaded numeric measurements and coefficients. A malformed, inconsistent, or incompatible advisory profile is ignored without affecting execution.
- Keep profile writes atomic and collision-safe. Profile and benchmark files belong under the project `target/`; never use `/tmp` for JIT artifacts or measurements.
- Keep helper callbacks synchronous and bounded by their frame contracts. BigInt results share the JIT root arena, capped at 65,536 values; a full arena falls back before the current operation. The compiled-callee adapter is limited to compatible side-effect-free bodies. The synchronous VM bridge handles other eligible calls.
- Expose decision reasons in debug output: warming, bootstrap probe, adaptive compile, budget defer, full cache, unsupported candidate, fallback cooldown, compile failure, and invalid native frame.

## Completed V1 implementation slices

### 1. Native exit validation and fallback lifecycle — implemented

Validate all native return fields before frame restoration. Preserve the original VM frame on rejection. Keep runtime `FaultAt` and dynamic `ResumeAt` distinct from deterministic code-generation failure, and add a bounded retry policy so a fallback cannot cause an OSR attempt on every loop iteration.

**Acceptance:** status/reason/PC/depth combinations are checked centrally; errors are reproduced by the VM; malformed exits cannot mutate VM locals or stack; supported runtime values can still use the compiled function after a different value falls back.

### 2. APE cost, heat, and profile hardening — implemented

Make token admission work when a measured compilation exceeds bucket capacity, and carry actual cost as temporary debt. Stop persisting run-local heat. Reset a hot streak after a meaningful idle interval. Validate profile values, use unique atomic temporary paths, and print the reason behind each compile/defer/skip decision.

**Acceptance:** a candidate whose conservative estimate exceeds the token capacity can still be considered when the bucket is full; overspend delays later work; a previous run's hot history cannot make a cold current run look active; invalid profile data falls back to seeded estimates.

### 3. Reproducible VM/JIT benchmark — implemented; local release baseline recorded

Add a dedicated harness that compiles each source once, compares the same workload and output through VM and JIT, times the first JIT invocation separately from retained-plan invocations, and reports compile/native profile data plus median and spread. Keep generated profiles under `target/jit-bench/`, remove only files owned by the harness, and never call the existing temp-directory runtime benchmark.

**Acceptance:** the report identifies whether compilation and calibration actually occurred, shows VM steady-state, first JIT invocation, and retained-plan JIT samples separately, and validates output equality before reporting timings.

Release measurement on one Intel Core i7-12700H Linux x86_64 host with APE profile version 11 (1,000,000 loop iterations, seven retained-plan samples):

| Workload | VM median | First JIT-enabled run | Retained JIT-enabled median (P10–P90) | Compile cost | VM / native ns per backedge |
| --- | ---: | ---: | ---: | ---: | ---: |
| `int` | 586,116 µs | 43,971 µs | 13,074 µs (12,113–13,403) | 3,868 µs | 630 / 21 |
| `uint` | 599,874 µs | 191,017 µs | 14,177 µs (13,945–14,404) | 3,659 µs | 661 / 24 |
| `float` | 619,383 µs | 75,453 µs | 14,442 µs (13,481–14,591) | 3,794 µs | 690 / 20 |
| `enum` | 1,077,461 µs | 61,748 µs | 24,300 µs (24,203–24,593) | 5,475 µs | 1,194 / 36 |
| `mixed-int-float` | 3,211,448 µs | 402,739 µs | 117,003 µs (116,011–118,094) | 13,623 µs | 1,688 / 105 |
| `bigint-float` | 1,658,139 µs | 147,133 µs | 73,378 µs (71,405–75,440) | 13,507 µs | 1,841 / 80 |
| `bigint-arithmetic` | 1,618,954 µs | 244,986 µs | 46,484 µs (45,711–47,514) | 9,472 µs | 1,761 / 54 |

The enum workload checks both the enum and its active `Signal::Hit` variant on each iteration. The mixed workload exercises signed and unsigned integer comparisons against a float. The BigInt/float workload compares `9007199254740993` against `9007199254740992.0`, above the binary64 integer-precision boundary. The BigInt arithmetic workload covers compact signed add/multiply, compact unsigned add/subtract, unsigned subtraction producing `-1`, and a final signed-boundary overflow that resumes in the VM. The first run includes APE warmup and is not a pure compile-time measurement. APE reported calibrated native execution for all seven cases, and every run produced identical output. The single profile `native ns/backedge` estimate is noisier than the seven retained timing samples; use the retained median and P10–P90 range for comparisons. BigInt arithmetic was about 34.8 times faster in the retained median on this host. These tight loops are microbenchmarks on one host and do not predict application-wide speedups. The retained-plan samples reuse one `Program`, so their compilation cost is already paid.

### 4. Expand low-risk scalar lowering — implemented for this slice

Add scalar comparisons only where the VM defines a simple identical operation (notably `char` ordering, `bool` equality, `nil` equality/inequality, and exact mixed numeric comparisons). Mixed integer-to-float lowering follows the VM's exact range and truncation rules. Add paired VM/JIT cases for both true and false branches and retain interpreter fallback for other mixed numeric and aggregate comparisons.

**Acceptance:** native compilation is confirmed in the profile and all outputs/errors match the VM for boundary and fallback cases.

### 5. Broaden safe frame values and record a release baseline — implemented

Permit OSR when locals contain values that native code only carries through tagged slots. The frame roots and restores such values without exposing their payloads to generated code; unsupported operations still fall back. Add a VM/JIT regression with a string parameter live across the loop. The release benchmark shows a repeatable retained-plan benefit for the measured scalar loops.

**Acceptance:** opaque values survive OSR without loss of identity or lifetime; all matched scalar workloads pass; release timings are recorded with build mode, host, iteration count, samples, compilation cost, and calibration status.

### 6. Expand guarded expressions and types — implemented for this slice

Intern user enum tags from the verified artifact. The frame keeps each variant's full Cog object rooted while generated code compares a compact id for `enum` and exact `Enum::Variant` predicates. Enum-wide tests are limited to 32 registered variants to keep generated code size predictable. Unknown tags, larger enums, and `Error` values resume in the interpreter, so an incomplete registry cannot turn a valid match into `false`. The APE profile version advances when this lowering changes.

**Acceptance:** enum and individual-variant predicates match the VM for matching and non-matching cases; full payload values survive OSR; unsupported nominal values take the interpreter fallback.

### 7. Guard compact BigInt operations and reduce frame traffic — implemented for this slice

BigInts that fit in `i64` or `u64` use a tagged scalar payload for exact same-type and mixed comparisons against `int`, `uint`, and `float`. The JIT tag retains the root index, and frame restoration verifies the payload against the original BigInt before restoring its original Cog type. The BigInt type test recognizes both compact and arbitrary-precision rooted slots. Values outside those ranges resume in the VM. APE profile version 8 invalidates measurements collected before this lowering change.

Local slots are promoted to Cranelift SSA variables across reachable OSR blocks. A `Load` reads the SSA value; a `Store` updates it and marks the local state dirty without writing the VM frame. A shared native exit block writes the locals back only when needed, before any fallback, fault, completion, or profile slice. Bytecode that cannot be reached from a valid OSR entry is not lowered. This does not rely on source `const`: both `const` and `var` locals use the same SSA path, while constants exposed by bytecode may be folded by Cranelift. APE profile version 10 invalidates measurements collected before this machine-code change.

BigInt add, subtract, multiply, divide, and remainder use native integer operations when both operands have the same compact signed or unsigned representation. Results are stored in unrooted tagged slots and reconstructed as Cog BigInts when the frame returns to the VM. Checked overflow and unsupported operand representations resume before the operation with the original operands intact; unsigned subtraction can produce a negative result when it fits in `i64`. Division by zero faults through the VM; signed minimum divided by negative one resumes in the VM because its valid BigInt result does not fit in signed 64 bits. Larger BigInts and mixed compact representations also remain in the VM. Runtime limits disable JIT, so the digit-limit checks remain owned by the interpreter. String and aggregate operations also remain in the VM. Float remainder stays in the interpreter unless the target operation can reproduce Cog's exact remainder and error behavior.

**Acceptance:** paired benchmarks compare BigInt accumulation, multiplication, signed and unsigned division/remainder, and the signed-boundary fallback against the VM, and verify identical output before reporting timings. APE profile version 12 invalidates measurements collected before this lowering change. Treat the measured difference as local microbenchmark evidence, not a workload-wide guarantee.

### 8. Compare compact BigInts across signed representations — implemented for this slice

BigInt comparisons now use the exact mixed-signedness integer comparison path when both operands fit in the compact signed or unsigned 64-bit representations. Negative signed values order below all unsigned values; nonnegative signed values compare by their unsigned payload. This covers equality, inequality, and ordering without converting through floating point. Arbitrary-precision values continue to resume in the VM.

**Acceptance:** the paired `bigint-compare` benchmark exercises both operand orders, negative and nonnegative signed values, unsigned values above `i64::MAX`, all ordering relations, and equality/inequality; it checks output against VM execution before reporting timings. On this host, 100,000 iterations over three retained samples took 422.015 ms in the VM and 16.385 ms with JIT enabled after compilation (about 25.8× faster); the first JIT-enabled run took 171.003 ms including compilation. APE profile version 13 invalidates measurements collected before this lowering change. Treat these figures as a local microbenchmark result, not a workload-wide guarantee.

### 9. Lower compact mixed-representation BigInt arithmetic — implemented for this slice

Addition, subtraction, and multiplication between a compact signed BigInt and a compact unsigned BigInt use an exact `i128` intermediate. The result is reduced to the compact tagged representation only when a signed or unsigned 64-bit round trip proves it fits; otherwise execution resumes at the original VM instruction. Mixed-representation division and remainder remain in the VM.

**Acceptance:** the paired `bigint-mixed-arithmetic` benchmark exercises both operand orders, negative and nonnegative results, and the signed `i64` boundary while checking its output against VM execution. `bigint-mixed-overflow` separately checks that an out-of-range mixed subtraction resumes at the original VM instruction and preserves the exact result. On this host, 100,000 iterations over three retained samples took 303.495 ms in the VM and 13.531 ms with JIT enabled after compilation (about 22.4× faster); the first JIT-enabled run took 119.981 ms including compilation. The overflow case produced identical output and correctly remained uncalibrated because every operation resumed in the VM. APE profile version 14 invalidates measurements collected before this lowering change. Treat these figures as local microbenchmark results, not a workload-wide guarantee.

### 10. Keep BigInt render loops and pixel writes in native execution — implemented; benchmark added

Large BigInt arithmetic and comparisons now use private runtime helpers that preserve the exact Cog values and return to the VM when a helper cannot safely handle an operation. Numeric `str::to_bigint`, indexed `bytes::set`/`bytes::get`, `JumpIfNoPropagation`, and direct calls to already-calibrated pure Cog functions can stay in the same JIT slice. Direct callees use a reusable child frame and isolated roots so temporary BigInts from one pixel do not accumulate across every pixel. Unsupported error-construction paths remain precise VM fallback edges. The root arena is bounded; exhaustion falls back before the active instruction. APE profile version 15 discards old native timing data after this change.

The new `mandelbrot-render` case in `src/bin/bench_jit.rs` reproduces the full fixed-point inner render path at a smaller image size without SDL. It compares the VM and JIT outputs through the existing benchmark harness and reads the rendered byte buffer into a checksum so both runs must produce identical pixels. No performance result has been recorded for this new workload yet; measure it on the target machine before judging the end-to-end benefit.

### 11. Reuse local frame slots from CFG liveness — implemented

After constant propagation and reachability rewriting, the bytecode optimizer computes local `Load`/`Store` liveness per callable and greedily colors the interference graph. Locals that are live at the same point keep distinct slots; disjoint lifetimes can share one. The pass only rewrites local slot operands, runs before bytecode validation, and falls back unchanged when a region exceeds its instruction, slot, dataflow, or interference budget. The VM's slot quota remains active, while shorter frames use fewer slots and JIT OSR visits fewer roots.

The `slot-pressure` benchmark declares 200 temporary bindings in a hot loop. The optimized `work` function uses four local slots, including its parameter and loop state; the 200 short-lived temporaries share one slot. At 100,000 iterations over three retained samples, the VM median was 1,382,599 µs, the first JIT-enabled run was 114,512 µs, and retained JIT execution was 16,955 µs (P10–P90: 16,457–17,032 µs). The benchmark reported 18,487 µs compilation cost, 13,793 VM / 2,187 native ns per backedge, and calibrated execution; VM and JIT outputs both were `4999950000`. The bytecode artifact was 18,085 bytes. A 240-binding variant exceeded the current 512-instruction JIT eligibility limit and remained interpreted, even though its frame also compacted to four slots. These measurements show frame compaction and successful JIT execution, but do not isolate a before/after runtime speedup from compaction itself.

## Current limits

These exclusions describe current scope; they are not delivery commitments. See
the [roadmap](../ROADMAP.md) for accepted future work.

- JIT compilation in the background, preemptible compilation, and hard compile-latency guarantees.
- Machine-code eviction, persistent native code, and cross-process code caches.
- Async suspension, metered execution, and SDK callback reentry across the bridge.
- Adaptive inline caches for indirect callable targets and native lowering of
  mutable-cell operations. A closure can access and update cells through the VM.
- A native calling convention between compiled functions. Every compiled call
  still crosses a Rust helper that validates arguments and the callee's exit.
- Full coverage of collection and string operations.

- Training a portable CPU model from benchmark data or adapting coefficients across unrelated bytecode artifacts.
